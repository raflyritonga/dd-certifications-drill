Agent: turning logs on, files, commands

Exam-heavy

# /etc/datadog-agent/conf.d/myapp.d/conf.yaml
logs:
  - type: file
    path: /var/log/myapp/*.log

Agent filtering and scrubbing

Exam-heavy

Rules run on the host before logs leave it, in list order, each on the output of the previous one. Patterns are Golang regexp. Per source: log_processing_rules. Global: logs_config.processing_rules in datadog.yaml (or DD_LOGS_CONFIG_PROCESSING_RULES). A source's own rules replace the global rules for that source.

Rule typeEffect
exclude_at_matchDrop the log if the pattern is found in the message. The way to filter specific logs out by value
include_at_matchSend only logs that match. Several include rules = all must match (AND); for OR use one rule abc|123
mask_sequencesReplace matches with replace_placeholder (capture groups $1, ${2} from 7.17). The way to keep a log but hide sensitive data before it leaves the host
exclude_truncatedDrop logs the Agent truncated (7.69+, no pattern)
multi_linePer source only: join lines until the pattern (start of a new log) appears again
 
logs:
  - type: file
    path: /var/log/app/app.log
    service: cardpayment
    source: java
    log_processing_rules:
      - type: exclude_at_match
        name: exclude_healthchecks
        pattern: healthcheck
      - type: mask_sequences
        name: mask_credit_cards
        replace_placeholder: "[masked_credit_card]"
        pattern: (?:4[0-9]{12}(?:[0-9]{3})?|[25][1-7][0-9]{14})
      - type: multi_line
        name: new_log_start_with_date
        pattern: \d{4}\-(0?[1-9]|1[012])\-(0?[1-9]|[12][0-9]|3[01])

Multi-line

  • Manual multi_line pattern must match the start of a log; a pattern that never matches can lose lines
  • Automatic detection: Agent 7.65.0+, on by default from 7.82.0. A datetime in the first 60 bytes starts a new log; JSON is never aggregated
  • Disable with logs_config.auto_multi_line_detection: false; tune with auto_multi_line_detection_custom_samples
  • 7.67+ compacts pretty-printed JSON before processing rules, so "key": "value" patterns stop matching
  • In labels and annotations escape \d as \\d and keep valid JSON

Sensitive Data Scanner (in Datadog)

  • Scans after logs reach Datadog, before indexing. Use Agent mask_sequences when data must not leave your environment
  • Scanning group (filter + products) holds scanning rules (library or regex). New groups are disabled by default
  • Actions: Redact, Partially redact, Hash (irreversible), Mask (unmask with data_scanner_unmask). Sampling blocks obfuscating actions
  • Only new data is scanned. Already-indexed sensitive logs: restriction query on the Data Access page, or Logs Data Deletion (cancellable 10 days; derived metrics are not deleted)

Pipelines

Exam-heavy

Order: JSON preprocessing → every pipeline whose filter matches, in list order, all its processors in sequence → indexes. Processing happens at ingestion, so changes only affect new logs.

Rules

  • A log is tested against every pipeline filter and can be changed by several pipelines
  • The filter is evaluated before the pipeline's processors: you cannot filter on an attribute the same pipeline extracts
  • Nested pipelines: one level only; a nested pipeline holds processors only
  • Best practice: ≤ 20 processors per pipeline, ≤ 10 parsing rules per Grok parser
  • No integration for your source? Create a custom pipeline filtered on that source (source:my-app) and add processors

Integration pipelines

  • Installed automatically when the first log with that source arrives
  • Read-only: clone to edit (the clone of a pipeline starts disabled). Cannot be deleted, only disabled
  • They parse the technology's default format; a custom format needs a cloned or custom pipeline
  • Pipeline Library lists every integration pipeline
When processors write the same attributeProcessors
Last write winsGrok, Category, Arithmetic, String builder, Lookup, URL, User-Agent, GeoIP, Decoder
First write winsStatus, Service, Message, Trace and Span remappers
Last one wins (exception)Log Date Remapper
override_on_conflict (default false)Attribute Remapper, Array Map
  • Preview pipeline changes: a live tail processed with your edits; compare Your changes / Entire pipeline; filter All / Impacted / Not impacted logs.
  • Pipeline Scanner: tags matching logs with the pipelines and processors that changed them for 15 minutes; 3 concurrent sessions, 12 per 12 hours; needs logs_read_config + logs_write_pipelines.
  • Unparsed logs: query datadog.pipelines:false; Patterns view kick-starts parsing rules. Auto-Processing parses logs that match no pipeline (on by default for orgs created from Nov 4, 2026; a * pipeline filter turns it off).
  • Permissions: logs_write_pipelines (pipelines), logs_write_processors (processors), logs_read_config.

Search syntax

Exam-heavy

A search = time range (top right) + query. Operators are case-sensitive: AND (default when omitted), OR, - (exclude).

QueryFinds
status:error infoError logs whose message contains the word info (the practice answer writes it status:error and info)
hello · "hello world"Free text in message, @title, @error.message, @error.stack · exact phrase (straight quotes)
*:helloFull text across all attributes. Not allowed in Live Tail, index, archive, pipeline, rehydration or log-based metric filters
service:web-app · env:prodReserved attribute or tag: no @
@http.status_code:500Any other attribute: @ prefix. Attribute values are case-sensitive
service:(web-store OR auth)Either value. A log has one service, so (a AND b) on it matches nothing (the practice answer key still gives source:nginx AND source:redis)
service:payments -host:canary-01Exclusion
@http.status_code:[400 TO 499] · @duration:>20msRange and comparison: add the attribute as a facet or measure first
web* · service:*mongo · waiting**timeWildcard inside a word · on a value · across words
@my_attr:hello\:world or @my_attr:"hello:world"Escape special characters with \ or quote the value
-@http.status_code:*Logs without that attribute
CIDR(@network.client.ip, 13.0.0.0/8)IP in a range; negate with NOT(...). Works in Live Tail and monitors
@user_perms:(4 6) · @user_perms:[2 TO 6]Array contains both · contains one value in range
tags:my_tag · #latency_gap:>100Tag without a key · calculated field
  • Free text matches whole words: hello-world splits into two words, my.friend is one word (use *friend), 192.168.1.1 is one word.
  • Special characters to escape: - ! && || > >= < <= ( ) { } [ ] " * ? : \ # and spaces. / needs no escape.
  • No facet is needed for key:value search; facets add autocomplete and analytics.

Log Explorer functionality

Exam-heavy

List view and columns

  • Move a column: drag and drop it by its handle (6-dot icon) in the header row
  • Add a sortable column: from both the List Options menu and the facet panel (practice answer); the docs also allow the log side panel
  • Sort, rearrange, remove from the header row. Sorting is reliable only on facets
  • Default sort: timestamp, newest first (fastest)
  • Options also sets Content Height and Content Display

Facets and measures

  • Facet (dimension): string or integer, top values, unique counts, filtering
  • Measure: number with optional unit (TIME, BYTES); aggregate, range filter, sort
  • From the side panel: string → facet only; number → facet or measure
  • New facets fill in for new logs only. Keep under about 1000 facets
  • Hiding a facet is personal and does not affect monitors, Live Tail or dashboards

Side panel

  • Top: context (host, container, tags). Bottom: message and attributes
  • View in context: lines just before and after, even if they don't match the filter
  • Metrics tab: 30 minutes around the log. Trace tab needs trace ID injection
  • Share: copy the log JSON or Share Event. Save to notebook keeps the log past retention

Saved views and calculated fields

  • Saved view = query + live time range + visualization + facet subset + columns
  • Default view: private to you. Integration views read-only; custom views shared, editable by all but Read Only users
  • Calculated fields: query-time, #name, private, temporary, up to 5. Good for already indexed logs
  • Watchdog Insights banner: Log Anomaly Detection and Error Outliers for the current query

Log-based metrics

Exam-heavy
Retention15 months10-second granularity
Computed onAll ingested logsIncluding logs excluded from indexes
BillingCustom metricsEach tag combination; percentiles count too
Permissionlogs_generate_metricsStandard role by default

Create

  • Log Explorer Export → Generate new metric (long-term KPIs), or Logs > Generate Metrics > + New Metric
  • Query on the ingest stream: no *:term full text; only logs timestamped within the last 20 minutes
  • Field * = count; a numeric attribute = distribution (count, sum, min, max, avg; optional p50-p99)
  • No tags unless you group by; avoid user IDs, request IDs, timestamps
  • Name: starts with a letter, ASCII letters, digits, _, ., max 200 chars

Change and cost

  • Editable: query, group-by, percentiles. Not editable: name and type (create a new metric)
  • No backfill: values start when the metric is created
  • Distribution = 5 × tag combinations; with percentiles 10 ×
  • Pattern to cut cost: metric on 200 OK logs, then exclude them from the index

Archives

  • All ingested logs, indexed or not, to your S3, Azure Storage or GCS. Logs go to the first archive whose filter matches
  • Compressed JSON, zstd default (gzip optional), path /dt=YYYYMMDD/hour=HH/
  • S3: s3:PutObject to write, s3:GetObject + s3:ListBucket to read back. No Azure immutability, no GCS retention policy
  • Check the bucket after 15 minutes. Permission logs_write_archives

Reading archives back

  • Archive Search (recommended): no re-indexing, 100,000 logs kept 24 hours, no aggregations
  • Rehydration: historical view by time range + query, up to 1 billion logs, exclusion filters ignored, default retention 15 days
  • Scan size = everything in the time range, so shorten the range to save cost
  • Forwarding to Splunk, Elasticsearch, HTTP, Sentinel, Google SecOps: Custom Destinations
  • Logs Search API: API key + application key, max 1,000 logs per page, cursor pagination

Why logs, Logging without Limits, storage tiers

What each signal is good at

  • Logs: timestamped records of discrete events. Root cause (the exact error, stack trace, user, request), audit trail, security forensics
  • Metrics: numbers over time. Health at a glance, long-term trends, cheap alerting
  • Traces: time spent per request across services. "Time in code, CPU, GC, lock contention, I/O" is profiling, not logs
  • Correlate: log side panel Metrics tab; click a graph point > View related logs

Logging without Limits

  • Decouples ingestion from indexing: ingest and process everything, index what you need, archive everything, generate metrics from everything
  • Lifecycle: intake → JSON preprocessing → pipelines → Live Tail → indexes / archives / log-based metrics
  • Excluded or over-quota logs: not searchable in the Explorer, but still in Live Tail, archives, log-based metrics and Cloud SIEM
  • Noise workflow: Patterns view → pattern panel Add Exclusion Filter → Generate Metrics with the same query → anomaly monitor on that metric

Formats, reserved attributes, timestamps, limits

JSON is parsed automatically: every key becomes an attribute with no pipeline. Plain text, syslog, Apache/NGINX lines and key=value arrive as one message and need a Grok parser (or the matching integration pipeline).

Timestamps

  • Recognized: ISO8601, UNIX milliseconds, RFC3164. Epoch seconds or nanoseconds are not, and may be dropped
  • Accepted window: up to 18 h in the past (7 days in Preview) and 2 h in the future. Older logs are dropped at intake: datadog.estimated_usage.logs.drop_count
  • Stored in UTC, shown in your time zone. Epoch is read as UTC, so New York local time shows 5 h in the past
  • Grok date() outputs epoch ms but does not set the official date: add a Log Date Remapper. The last date remapper wins
  • Epoch seconds: remove timestamp from the preprocessing list, Arithmetic timestamp * 1000, then a date remapper

Limits per log

  • HTTP intake accepts up to 1 MB per log (larger is truncated, still 2xx); recommended ≤ 25 KB; the Agent splits at 900 KB
  • < 2048 attributes · keys < 50 chars · nesting < 20 levels · faceted values < 1024 chars
  • ≤ 100 tags per log, each ≤ 256 chars, 10 million unique tags per day
  • Null-valued attributes are not kept. Indexed grouped queries truncate message to 75 KiB, other fields to 25 KiB
  • Truncation metrics: datadog.estimated_usage.logs.truncated_count / _bytes
  • Multi-line: without aggregation each line of a stack trace is a separate log. Log in JSON, or aggregate at the Agent (see Agent filtering & scrubbing). Stack trace attributes with a dedicated display: error.stack, error.message, error.kind, logger.name, logger.thread_name.
  • The Agent assumes UTF-8; encoding: utf-16-le, utf-16-be, shift-jis for type: file. Every line must end with \n or \r\n, or it is never sent.

Tags and transport

  • Tags are key:value, start with a letter, up to 200 chars. DD_TAGS splits on whitespace
  • Unified service tagging: env, service, version (K8s labels tags.datadoghq.com/*, Docker labels com.datadoghq.tags.*)
  • Default transport: compressed HTTPS on 443 (6.19/7.19+). HTTPS test only at startup, TCP fallback until restart
  • logs_config.force_use_http: true; always force a transport behind a proxy. SOCKS5 proxy forces TCP
  • Batches: 1 MB, 900 KB per log, 1,000 logs; batch_wait 5 s (1-10); compression_level 6 (0-9)
  • TCP to the intake is not supported. Legacy endpoints only for US1 (10516 TLS, 10514 plain) and EU (443)

Grok parsing

Rule: RuleName %{MATCHER:EXTRACT:FILTER}. A rule must match the whole log; with several rules the first match top to bottom wins. Escape |, [, (.

# john connected on 11/08/2017
MyParsingRule %{word:user} connected on %{date("MM/dd/yyyy"):date}
# WARNING: John disconnected on 09/26/2017
status_rule %{word:log_status}: %{word:user.name} %{word:action}.*
kv_rule %{data::keyvalue}                      # key=value / logfmt
json_after_prefix %{word:level} %{data::json}   # JSON after a text prefix
Matcher / filterMatches or does
word · notSpace · dataLetters/digits/underscore · up to the next space · anything incl. spaces and newlines
number · integerDecimal as double · integer
date("pattern"[, "tz"])Parses to epoch ms. Timezone like UTC+1, Europe/Paris. Needs a date remapper to become the official date
regex("..."), ip, hostname, uuid, quotedString, booleanIngest-time only
keyvalue([sep[, allow[, quote[, delim]]]])Default separator =; keyvalue(": "), keyvalue("=","/:") for URLs, keyvalue("=", "", "", "|")
json · xml · csv(headers) · url · querystring · useragentStructured filters
nullIf("-") · lowercase · scale(factor) · array(...)Clean-up filters
  • Debug a rule with the star trick: end it with .* and remove attributes from the end until it matches. Common culprits: notSpace on a value with spaces, integer on a decimal.
  • Query-time parsing (calculated field extractions) supports only data, integer, notSpace, number, word.

Aliasing rules

  • Runs after pipelines; the log keeps both source and standard attribute
  • Type is enforced; if the cast fails, aliasing is skipped
  • Overrides an existing destination value; only one source is aliased if a log has several
  • Only to standard attributes; standard attributes cannot be aliased; user and user.name cannot both be standard
  • Applies to new logs only. Managed at Logs > Pipelines > Standard Attributes (admins)

Attribute Remapper vs aliasing

  • Remapper: inside a pipeline, order matters, can rename tags, removes the source by default (preserve_source: false) and does not overwrite an existing target (override_on_conflict: false)
  • Aliasing: configured on the standard attribute or facet ("Alias to..."), keeps the source
  • Aliased facets still work but are deprecated: use switch to alias

Exclusion filters

  • Sample 0-100% of individual logs or per attribute value (@user.email, trace ID)
  • Example: exclude 95% of source:nginx AND http.status_code:[200 TO 299]; keep a log-based metric for full counts
  • Toggling a filter off affects new logs only
  • Excluded logs stay in Live Tail, archives, log-based metrics and Cloud SIEM

Quota, retention, usage

  • Quota reached: not indexed, but still in Live Tail, archives, metrics. An event is generated; alert at 80%
  • Retention per index; out-of-contract 3, 7, 15, 30, 45, 60 days (Org Management enables it)
  • datadog.estimated_usage.logs.ingested_events / _bytes, free for 15 months; datadog_is_excluded:false = indexed
  • Deleting an index needs logs_delete_data; the name cannot be reused

Setup

  • Monitors > New Monitor > Logs, or Log Explorer Export → monitor (how to notify stakeholders from a search)
  • Monitor a log count, a facet's unique count, or a measure (avg, sum, percentiles...)
  • Simple alert = one alert overall; Multi Alert = one per group
  • Recovery threshold stops flapping; below 1 catches "no logs at all"
  • Count queries evaluate missing data as zero by default

Notification message

  • Dynamic links use template variables, e.g. https://app.datadoghq.com/dash/integration/system_overview?tpl_var_scope=host:{{host.name}}
  • {{#is_alert}}...{{/is_alert}}, {{#is_recovery}}, {{#is_warning}}
  • {{log.message}}, {{log.attributes.[error.message]}}, {{log.link}}
  • Up to 10 log samples or breaching values in the notification; not in recoveries
  • @slack-..., @pagerduty-..., @email; priority P1-P5
  • Need non-indexed logs, a window over 2 days or anomaly detection on long history? Create a log-based metric and a metric monitor.
  • Watchdog log anomalies need no setup; severe ones (error logs, at least 10 minutes) can trigger a Watchdog monitor.
