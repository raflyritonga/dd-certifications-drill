## Datadog Fundamentals drill

A single-page practice app for the Datadog Fundamentals certification. It works offline, in any browser.

- **Full exam simulation**: 90 questions in 2 hours, the same length and time limit as the real exam
- **20 mock tests** of 25 questions, each covering all nine exam topics
- **Focused drills**: ports and networking, allotments and custom metrics, a random 25, and retrying your mistakes
- **The official practice set**: Datadog's 25 practice questions, with explanations added
- **Practice by topic**, starting with questions you missed or haven't seen
- **Cheat sheet** covering every exam domain, with links to the source docs under each section

### Use it

Open `dd-fundamental/index.html` in a browser. Your scores are saved in that browser only; **Reset progress** in the header clears them.

| | Study mode | Exam mode |
|---|---|---|
| Feedback | Right after each answer, with every option explained | None until you submit, then a full review |
| Timer | None | 80 seconds per question, the real exam's pace |
| Topic labels | Shown | Hidden, like the real exam |
| Changing answers | Locked once you answer | Change answers and flag questions until you submit |

Keys: `1`–`3` or `A`–`C` to answer, `Enter` to continue, `Esc` to leave.

### About the questions

- **500 questions** in nine topics, weighted toward the areas the exam leans on most (ports and allotments):

  | Topic | Questions |
  |---|---|
  | Data Collection & Integrations | 80 |
  | Networking & Datadog Ports | 75 |
  | Allotments, Billing & Custom Metrics | 75 |
  | Computing Fundamentals | 60 |
  | Troubleshooting the Agent | 49 |
  | Tagging & Search | 45 |
  | Agent Installation & Keys | 41 |
  | Monitors & Alerts | 40 |
  | Dashboards & Host Map | 35 |

- **3 options per question**, one correct, matching the official practice exam.
- **Every option is explained**: why the right answer is right and why each wrong one is wrong, with a link to the docs page behind it.
- **Checked against the live Datadog docs and pricing pages in October 2026**, including renamed products and changed defaults.
- **Official practice set**: Datadog's answer key is kept as-is. Where the product has changed since, the explanation adds a "Current docs:" note.
- The questions are original. Nothing was copied from exam-dump sites.

## Project layout

| Path | What it is |
|---|---|
| `dd-fundamental/index.html` | The built app. Generated by the build script; don't edit it by hand |
| `dd-fundamental/questions/pool_*.json` | Question banks by topic: `fund`, `net`, `allot`, `agent`, `data`, `viz` |
| `dd-fundamental/questions/official.json` | The official practice set, with explanations added |
| `dd-fundamental/src/template.html` | App UI (HTML, CSS, JavaScript) |
| `dd-fundamental/src/cheatsheet.html` | Cheat sheet content and its source links |
| `dd-fundamental/src/build.py` | Checks the questions, deals them into 20 balanced mock tests, and writes `index.html` |
| `dd-fundamental/materials/` | Exam guide, practice exam and study notes. Git-ignored and not needed to build |

## Edit and rebuild

Edit the JSON files in `dd-fundamental/questions/` or the files in `src/`, then rebuild:

```bash
cd dd-fundamental && python3 src/build.py
```

Each question looks like this:

```json
{
  "id": "net-002",
  "topic": "Networking & Datadog Ports",
  "subtopic": "Datadog Ports",
  "difficulty": "easy",
  "q": "What is the default port and protocol of the DogStatsD server bundled with the Agent?",
  "options": ["8126/TCP", "8125/TCP", "8125/UDP"],
  "answer": 2,
  "explanation": "DogStatsD listens on UDP 8125 by default. 8126/TCP is the APM trace receiver.",
  "notes": [
    "8126/TCP is the APM trace receiver.",
    "DogStatsD uses UDP, not TCP, on 8125.",
    "DogStatsD listens on 8125/UDP by default (enabled by default since Agent 6)."
  ],
  "ref": "https://docs.datadoghq.com/developers/dogstatsd/",
  "verified": "2026-10"
}
```

- `answer` is the 0-based index of the correct option. Options are shuffled every time a question is shown.
- `notes` has one entry per option, in the same order.
- Use `\n` in `q` to show a config or code snippet. Wrap inline code in backticks.

The build prints a `PROBLEM` line and exits with an error code if a question doesn't have exactly 3 options, has an out-of-range `answer`, repeats an option, is missing its text or explanation, or reuses an `id` or question text. It still writes `index.html`, so fix any problems and rebuild.
